# 05_pjt — Pulse 주식 커뮤니티 댓글 분석 시스템

회사명을 입력하면 외부 증권 서비스에서 첫 번째 검색 종목을 자동 선택하고, 커뮤니티 댓글을 수집·정제·증강·요약하는 Django 웹 서비스입니다. 결과는 단계별 데이터와 함께 DB에 저장되며 저장된 분석 결과도 다시 조회할 수 있습니다.

## 구현 결과

- 검증 기업: **엑스게이트** (`A356680`)
- 원본 댓글: **20개**
- 정제 댓글: **17개**
- `gpt-5-nano` 증강 댓글: **17개**
- 최종 통합 데이터셋: **34개**
- 정상 길이 범위: **5~42자**
- AI 댓글 요약: 생성·저장·출력 완료
- Django 시스템 검사 및 DB 마이그레이션: 정상

커뮤니티 댓글과 생성형 모델 응답은 실행 시점에 따라 달라질 수 있습니다.

## 실행 방법

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
python manage.py migrate
python manage.py runserver 127.0.0.1:8000
```

### Git Bash

```bash
python -m venv .venv
source .venv/Scripts/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py runserver 127.0.0.1:8000
```

`.env`에 발급받은 `GMS_KEY`와 `GMS_BASE_URL`을 입력한 뒤 `http://127.0.0.1:8000/`에 접속합니다. 모델은 환경 설정의 `gpt-5-nano`를 사용합니다.

저장된 결과는 다음 주소에서 크롤링과 AI 호출 없이 바로 확인할 수 있습니다.

- 최신 결과: `http://127.0.0.1:8000/results/latest/`
- 특정 결과: `http://127.0.0.1:8000/results/<id>/`

## 주요 구현 사항

크롤러는 동적 React 화면에서 오래된 요소 참조로 발생하는 `stale element`를 피하도록 반복마다 DOM 요소를 다시 조회합니다. 검색 결과와 댓글 영역은 단일 클래스 이름에만 의존하지 않고 여러 후보 선택자와 텍스트 기반 대체 경로를 사용합니다.

LLM 응답은 바로 저장하지 않고 JSON 형식, 리스트 여부, 원본 인덱스 범위와 결과 개수를 검증합니다. API 호출에는 타임아웃을 적용하고, 실패 시 내부 예외와 긴 스택 트레이스를 화면에 노출하지 않고 사용자가 다시 시도할 수 있는 안내를 제공합니다.

전처리는 불필요한 공백과 특수문자를 정리한 뒤 길이 기준과 IQR을 함께 적용합니다. 원본·정제·증강·통합 결과와 처리 기준을 한 레코드에 보관해 실행 결과를 추적할 수 있습니다.

## 학습 내용

- 동적 웹페이지에서는 Selenium 요소를 오래 보관하지 않고 필요한 시점에 다시 찾아야 DOM 갱신 오류를 줄일 수 있었습니다.
- 생성형 모델 출력은 형식과 범위를 검증해야 후속 파이프라인과 DB 저장을 안정적으로 연결할 수 있었습니다.
- 오래 걸리는 외부 작업에는 로딩 상태, 타임아웃, 이해하기 쉬운 실패 메시지가 함께 필요했습니다.
- 단계별 입력과 출력을 저장하고 한 화면에서 비교해야 전처리와 증강 결과를 설명할 수 있었습니다.

## 느낀 점

한 번 성공하는 크롤링 코드보다 사이트 변경과 네트워크 지연을 견디는 구조가 더 중요했습니다. 전처리와 AI 증강도 결과만 출력하는 데서 끝나지 않고 단계별 데이터, 처리 기준, 출처를 함께 남겨야 신뢰할 수 있었습니다. 콘솔에서 분리해 만들었던 기능을 Django 요청 하나로 연결하고, 사용자가 진행 상태와 결과를 확인하는 흐름까지 완성했습니다.
