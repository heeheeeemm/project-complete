# 04-pjt : 인증 페이지 구현 (책담)

**책담**은 AI 기반 도서 분석과 창작 지원 통합 솔루션 서비스의 인증 시스템과 도서 CRUD를 구현한 프로젝트입니다.
회원 인증, 독서 프로필, 도서 관리, AI 작가 정보 생성 기능을 제공하며, 실제 책 표지와 장르별 탐색 기능을 추가했습니다.

## 실행 방법

### Windows PowerShell

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

이미 `.env`가 있으면 복사 명령을 생략합니다. `.env` 파일에 본인의 GMS 키를 입력합니다.

```dotenv
GMS_API_KEY=본인의_GMS_API_키
```

```powershell
python manage.py migrate
python manage.py runserver
```

접속 주소: **http://127.0.0.1:8000/books/**

Git Bash에서는 가상환경을 다음과 같이 활성화합니다.

```bash
source venv/Scripts/activate
```

- GMS 모델은 명세에 따라 `gpt-5-nano`를 사용합니다.
- 키가 없거나 외부 API 연결에 실패해도 회원 기능과 도서 CRUD는 사용할 수 있습니다.
- `.env`, 가상환경, 개인 DB는 Git에 포함하지 않습니다. 처음 실행하면 마이그레이션 후 회원가입과 도서 등록을 진행하면 됩니다.

- 도서 목록과 상세는 로그인하지 않아도 조회할 수 있습니다.
- 도서 등록·수정·삭제, 회원정보 수정·비밀번호 변경·탈퇴는 로그인한 사용자만 이용합니다.
- 로그인 여부에 따라 Navbar와 등록·수정·삭제 메뉴가 달라집니다.
- 변경 요청은 POST와 CSRF 토큰으로 보호하고, 없는 사용자·도서는 404로 처리합니다.
- 평점은 **0~10 사이의 정수**만 허용하며, 잘못된 값은 오류를 표시하고 저장하지 않습니다.

### 심화 기능

#### F417 — AI 작가 정보 생성 및 저장

1. 등록한 도서의 저자명으로 위키피디아에서 작가 문서와 프로필 사진을 검색합니다.
2. 동명이인 문제를 줄이기 위해 작가 조건을 추가하고, 문서 제목과 소개를 대조합니다.
3. 도서 제목·저자·설명과 검색 자료를 GMS의 `gpt-5-nano`에 전달합니다.
4. JSON 응답의 소개·대표작 형식을 검증하고 `author_info`, `author_works`, `author_image`, `author_source`에 저장합니다.
5. 상세 화면에 소개·대표작·사진이 있는 경우 사진·출처·AI 안내 문구를 표시합니다.

도서 등록 시 자동으로 생성하며, 상세 화면에서 **작가 정보 생성/다시 생성**을 할 수도 있습니다.
인증 오류·사용 한도·연결 실패를 구분해 안내하고, 실패해도 도서와 기존 생성 결과는 보존합니다.
저자를 변경하면 기존 작가 정보를 지우고 새 작가로 다시 생성합니다.

> 작가 대표작과 작가 정보는 AI가 생성한 정보로, 정확하지 않을 수 있습니다.

작가 정보 생성 URL: `/books/<pk>/author-info/` — 로그인 필요, POST 전용.

#### F418 — 추가 회원정보와 관심 장르

- 성별, 나이, 주간 평균 독서 시간, 연간 독서량, 관심 장르를 저장합니다.
- 나이·독서 시간·독서량은 입력 시 양의 정수만 허용합니다.
- 관심 장르는 최대 600자의 `CharField`에 저장합니다.
- `MultipleChoiceField`와 `CheckboxSelectMultiple`로 관심 장르를 복수 선택합니다.
- 선택 목록을 `','.join()`으로 저장하며, 수정 화면에서는 `split(',')`으로 기존 선택을 복원합니다.
- 추가 정보가 없는 기존 회원도 사용할 수 있도록 미입력을 허용합니다.

#### F419 — 개인 프로필

`/accounts/profile/<username>/`에서 아이디·이메일·이름·가입일과 독서 정보를 확인할 수 있습니다.
Navbar의 **내 프로필**에서 이동하며, 회원정보 수정·비밀번호 변경·탈퇴 기능은 본인 프로필에서 제공합니다.

### 추가 기능

- **장르 한 개 선택:** 소설·시·에세이·인문·과학·역사·경제·경영·자기계발·예술·기타를 선택합니다.
- **세부 장르:** 소설의 판타지·추리·로맨스·SF, 과학의 물리·화학·생명 등 대분류별 세부 장르 하나를 선택합니다. 대분류와 맞지 않는 조합은 서버에서도 거절합니다.
- **2단계 필터:** 전체보기 → 대분류 → 세부 장르로 탐색하며 선택 상태와 해당 도서 권수를 표시합니다. 전체보기에서도 세부 장르를 바로 선택할 수 있습니다.
- **실제 표지:** 한국어 제목은 알라딘을 우선 검색하고 Open Library·Google Books도 조회합니다. 제목·저자를 대조한 표지를 서버에 저장해 미리보기·목록·상세에 표시하며 출처를 제공합니다. 표지가 없으면 기본 표지를 사용합니다.
- **외부 연결 실패 대응:** 표지는 저장된 로컬 이미지를 재사용하고, Bootstrap CDN에 연결할 수 없어도 기본 레이아웃과 폼을 사용할 수 있습니다.

**자동 테스트 40개 통과.** 회원 인증·권한, 도서 CRUD, 장르 조합·필터, 독서 프로필, AI 응답 검증·실패 처리, 실제 표지의 저장·제공 등을 검증했습니다.
자동 테스트의 외부 API는 모의 응답을 사용하며, 실제 GMS 호출 성공은 사용자 실행 환경에서 별도로 확인했습니다.

## 학습 내용

- **커스텀 User 모델:** `AbstractUser`로 기본 인증 기능을 유지하면서 독서 관련 필드를 확장했습니다. `AUTH_USER_MODEL`을 초기 마이그레이션 전에 지정해야 한다는 점을 학습했습니다.
- **인증과 세션:** 인증 폼 검증 후 `login()`으로 세션을 만들고 `logout()`으로 제거했습니다. 비밀번호 변경 후에는 `update_session_auth_hash()`로 로그인 상태를 유지했습니다.
- **ModelForm:** 입력 검증·저장·오류 표시를 폼에 맡기고 `instance=`로 수정 대상과 기존 값을 연결했습니다. 수정 가능한 회원 필드를 명시해 관리자 권한이 노출되지 않도록 했습니다.
- **복수 선택 데이터:** 관심 장르는 폼에서 목록으로 다루고, 모델에는 쉼표 구분 문자열로 저장했습니다. 수정 시에는 기존 문자열을 목록으로 되돌려 체크 상태를 복원했습니다.
- **연관된 선택지:** 대분류 변경에 따라 세부 장르 선택지를 갱신하고, 서버에서도 올바른 조합인지 검증했습니다.
- **요청 방식과 접근 권한:** GET 조회와 POST 변경 요청을 구분하고 CSRF를 적용했습니다. 로그인 화면으로 이동하는 것과 원래 POST 요청을 재전송하는 것은 별개라는 점을 확인했습니다.
- **URL 이름공간:** `app_name`, URL 이름, `{% url %}`, `redirect()`를 사용해 템플릿과 view의 경로 의존성을 줄였습니다.
- **외부 API:** 검색 결과의 동명이인, 잘못된 JSON, 인증·사용량·연결 오류를 구분하고 실패 시 기존 데이터를 보존하는 방법을 학습했습니다.
- **데이터 보존과 검증:** 프로젝트·앱 이름 변경 시 설정·템플릿뿐 아니라 DB 적용 이력과 권한 정보도 연결해야 했습니다. 마이그레이션·자동 테스트·실제 브라우저 캡처를 함께 확인했습니다.

## 느낀 점

인증과 CRUD는 화면에 버튼을 만드는 것보다 입력을 검증하고 권한과 요청 방식을 구분하는 과정이 중요했습니다. 특히 회원정보 수정 폼에 노출할 필드를 명시하고, 비밀번호 변경 후 세션을 갱신하는 이유를 구현하면서 이해할 수 있었습니다.

외부 API는 정상 응답만 예상해서는 안 된다는 점을 느꼈습니다. 작가 한강 대신 강 이름이 검색되거나 국내 도서 표지가 검색되지 않는 상황을 겪으며, 검색 조건과 결과 검증이 필요하다는 것을 알게 됐습니다. 연결 실패가 도서 등록 실패로 이어지지 않도록 기능을 분리하고, 표지를 서버에 저장해 재사용하는 방식으로 개선했습니다.

장르 분류 기능도 데이터를 저장하는 것만으로는 충분하지 않았습니다. 사용자가 대분류와 세부 장르를 쉽게 선택하고, 현재 필터와 결과 권수를 바로 이해할 수 있어야 했습니다. 오류 안내와 화면 구성 역시 기능의 일부라는 점을 느꼈습니다.

기존 데이터를 유지하며 구조를 바꾸는 과정에서는 파일 이름 하나의 변경도 여러 참조에 영향을 줄 수 있었습니다. 자동 테스트와 실제 화면 확인을 병행하고, 요구사항별 캡처를 남기는 것이 결과를 점검하고 설명하는 데 도움이 됐습니다.
